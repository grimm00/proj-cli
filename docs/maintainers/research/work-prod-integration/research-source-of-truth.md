## 🎯 Research Question

Should the local registry or work-prod API be the source of truth for projects? This fundamental decision affects all sync logic, conflict resolution, and offline behavior.

---

## 🔍 Research Goals

- [ ] Goal 1: Understand trade-offs between local-first vs API-first patterns
- [ ] Goal 2: Identify conflict scenarios and resolution strategies
- [ ] Goal 3: Determine if different project types should have different truth sources
- [ ] Goal 4: Research industry patterns for local/cloud sync systems

---

## 📚 Research Methodology

**Sources:**
- [ ] Web search: Local-first software patterns and architectures
- [ ] Web search: Sync conflict resolution strategies
- [ ] Codebase analysis: Current registry and API implementation
- [ ] Case studies: Git (local-first), cloud note apps, package managers

## 🔑 Sub-Questions

1. **Conflict Resolution:** What happens when registry and API disagree?
2. **Orphaned Projects:** How do we handle projects that exist in one but not the other?
3. **Project Type Differentiation:** Should template-created projects have different truth sources than API-created projects?
