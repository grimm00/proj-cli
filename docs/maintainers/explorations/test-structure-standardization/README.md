## 🎯 Overview

Exploring how to standardize test directory organization for proj-cli, ensuring consistency with sibling projects (dev-infra, work-prod) while being appropriate for a Python CLI tool.

### Context

- Current proj-cli tests use a flat structure with `_integration` suffix convention
- README.md describes directories that don't exist (template leftover)
- dev-infra uses `unit/`, `integration/`, `regression/`, `smoke/` directories
- work-prod uses `unit/`, `integration/`, `performance/` directories
- Need to establish a standard that works for Python CLI projects
